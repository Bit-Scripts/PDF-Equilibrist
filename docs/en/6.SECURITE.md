## 1. Nature of the application

PDF Equilibrist is a **Windows desktop** application for editing PDF files.

| Characteristic | Value |
|---|---|
| Type | Native Windows application (exe) |
| Language | Python 3.12, compiled via PyInstaller |
| Interface | PyQt6 (Qt framework — no embedded browser) |
| Network | **No network connection during normal operation** |
| Remote storage | None — 100% local processing |
| Telemetry | None |
| Authentication | None (no account, no server) |
| Required privileges | Standard user — **no administrator rights** |
| Registry scope | `HKEY_CURRENT_USER` only |

## 2. Data flow

```
Local PDF file
      │
      ▼
PDF Equilibrist (isolated process, user space)
      │   in-memory read / modification
      ▼
Local PDF file (saved to disk via a local temporary file)
```

**No data ever leaves the workstation** during normal use.

### Exception: initial download of OCR models

The OCR feature (text recognition on scanned PDFs) uses **PaddleOCR**.
The inference models (~50 MB) are downloaded **once**, from PaddlePaddle's
official servers (`bj.bcebos.com`), the first time the OCR feature is used,
and are then cached under `%USERPROFILE%\.paddlex\`.

- A single outbound HTTPS connection, to a Baidu CDN
- Not triggered automatically — only when the user clicks an OCR button
- Can be pre-downloaded on a connected machine ahead of time and distributed
  via the `%USERPROFILE%\.paddlex\` folder, without ever requiring Internet
  access on the target machine

### 3.2 Identified attack vectors

The primary attack vector for a PDF editor is **a malicious PDF file**
exploiting a parser vulnerability when opened.

#### PDF parser — libmupdf / PyMuPDF

LibMuPDF is the most exposed library, since it directly parses PDF content,
including compressed streams, fonts, and embedded images.

**Known CVEs affecting libmupdf (examples):**

| CVE | CVSS severity | Type | Fixed in version |
|---|---|---|---|
| CVE-2023-31810 | 7.5 (High) | Heap buffer overflow on a malformed font | MuPDF 1.22 |
| CVE-2022-30974 | 5.5 (Medium) | Null pointer dereference | MuPDF 1.20 |
| CVE-2022-30975 | 5.5 (Medium) | Stack exhaustion (recursion) | MuPDF 1.20 |
| CVE-2021-4216  | 5.5 (Medium) | Floating point exception | MuPDF 1.19 |

**Mitigating context:**
- The application uses PyMuPDF **≥ 1.27**, which fixes all of the CVEs above.
- LibMuPDF is one of the most heavily audited PDF parsers (used in Evince,
  Okular, Ghostscript). Its codebase is regularly reviewed by the open-source
  community and the Artifex team.
- Exploitation requires the user to **deliberately open** a booby-trapped
  PDF — the vector is identical to Acrobat Reader, Foxit, or any other PDF
  reader.

#### Pillow (image processing)

Pillow has historically had CVEs related to processing malformed images
(buffer overflow while decoding TIFF/PNG). These vulnerabilities are
consistently fixed in minor releases.

**Notable recent CVEs:**

| CVE | Severity | Type | Fixed in |
|---|---|---|---|
| CVE-2023-50447 | 8.8 (High) | Code execution via a BMP image | Pillow 10.2.0 |
| CVE-2023-44271 | 7.5 (High) | DoS via an infinite TIFF image | Pillow 10.0.1 |

The application uses Pillow **≥ 10.4**, which covers these fixes.

#### PaddlePaddle (OCR engine)

PaddlePaddle loads inference models from disk. The serialization format
(`.pdmodel`) is controlled by Baidu and is not exposed to PDF content. An
attack via a malicious model would require compromising the
`%USERPROFILE%\.paddlex\` directory first — which already implies local
access to the machine.

## 4. Risk-reducing factors

### 4.1 Open source — continuous community review

The entire dependency stack is **open source** and published on GitHub.

- The source code is available for review by any developer or security
  researcher.
- CVEs are publicly disclosed and fixed within short timeframes (generally
  < 30 days for High/Critical severities).
- Major projects (PyMuPDF, Pillow, Qt) benefit from regular security audits
  funded by their maintainers or third-party organizations (OpenSSF, OSTIF, etc.).

### 4.2 Isolation — no services, no network

- The application starts **no network service** (no open port, no HTTP
  server, no listening socket).
- It has no network access except for the initial OCR model download.
- It does not read email, the clipboard, passwords, or system certificates.

### 4.3 Installation without elevated privileges

- The NSIS installer installs into `%LocalAppData%\Programs\PDF-Equilibrist`
  without UAC elevation.
- Registry keys created live under `HKCU` — strictly isolated to the current
  user profile.
- No system DLL is modified, no Windows service is registered.

### 4.4 Secure network saving

Saving to network shares (UNC, mapped drives, VPN/ZScaler) goes through a
local temporary file followed by `shutil.copy2()` — avoiding error-handling
issues in underlying C libraries when dealing with network paths directly.

## 6. Deployment recommendations

### Mandatory

- **Keep the application up to date**: every release rebuilds dependencies
  with their latest versions. Apply updates within a reasonable timeframe
  (≤ 30 days) after release.
- **Restrict usage to trusted PDFs**: like any PDF editor, do not open PDFs
  from unknown sources or unsolicited emails.
- **Pre-distribute the OCR models** if endpoints have no Internet access:
  copy `%USERPROFILE%\.paddlex\` from a reference machine.

### Recommended

- Add the exe to the **antivirus whitelist** (PyInstaller exes sometimes
  trigger false positives due to their compression structure).
- Add `bj.bcebos.com` to the **proxy/ZScaler whitelist** if OCR needs to be
  enabled without model pre-distribution.

### Optional — hardening

- **Sign the exe** with an EV code-signing certificate: removes SmartScreen
  warnings and proves the origin of the executable.
- Set up **centralized version control** (SCCM / Intune) to manage updates
  from IT.
