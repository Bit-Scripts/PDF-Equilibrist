## Prérequis

- Environnement conda `Equilibrist` configuré (voir [CONTRIBUTING](3.CONTRIBUTING.md))
- PyInstaller installé (`pip install pyinstaller`)
- Fichier `assets/logo/PDF-Equilibrist-logo.ico` présent (multi-résolution)
- Fichier `assets/Splashscreen.jpg` présent (image du splash screen)

---

## Étape 1 — Préparer les assets

```powershell
conda activate D:\Developpement\CONDA\envs\Equilibrist
cd D:\Developpement\PDF-Equilibrist
python tools/prepare_build.py
```

Ce script :
- Vérifie la présence du fichier `.ico` (ne le régénère pas — voir ci-dessous)
- Convertit `assets/Splashscreen.jpg` → `assets/splash.png` (600×338 px)

> ℹ️ Le fichier `.ico` multi-résolution fourni est conservé tel quel.
> Si vous devez le régénérer depuis le PNG, utilisez `tools/make_ico.py`.

---

## Étape 2 — Compiler l'exe

```powershell
pyinstaller PDF-Equilibrist.spec
```

L'exe est généré dans `dist/PDF-Equilibrist.exe` (fichier unique, ~80-120 Mo).

### Options utiles

```powershell
# Forcer un rebuild complet (ignore le cache)
pyinstaller PDF-Equilibrist.spec --clean --noconfirm

# Avec console de debug (pour diagnostiquer des crashs au démarrage)
# Modifier temporairement dans le spec : console=True
pyinstaller PDF-Equilibrist.spec
```

## Structure du spec

Le fichier `PDF-Equilibrist.spec` configure :

| Section | Description |
|---|---|
| `datas` | Assets embarqués (logo, boutons, splash, sources Python) |
| `hiddenimports` | Modules non détectés automatiquement (winreg, ctypes, PyQt6.QtPrintSupport…) |
| `excludes` | Modules à exclure pour réduire la taille (tkinter, matplotlib…) |
| `splash` | Splash screen PyInstaller (affiché avant que Python démarre) |
| `upx_exclude` | DLLs à ne pas compresser (zlib, vcruntime, Qt6…) |

### Pourquoi `upx_exclude` est important

UPX compresse les DLLs pour réduire la taille de l'exe. Certaines DLLs
critiques (zlib, vcruntime, DLLs Qt6) crashent au démarrage si compressées.
La liste `upx_exclude` du spec exclut ces DLLs de la compression.

## Étape 3 — Créer l'installeur NSIS

### Prérequis NSIS

- NSIS 3.x installé (`C:\Program Files (x86)\NSIS\`)
- Images BMP présentes :
  - `assets/installer/wizard_banner.bmp` — 164×314 px (page Bienvenue/Fin)
  - `assets/installer/wizard_header.bmp` — 150×57 px (en-tête pages intérieures)

### Compilation

```powershell
# Via PATH si NSIS est dans PATH
makensis installer\PDF-Equilibrist.nsi

# Chemin complet si NSIS non dans PATH
& "C:\Program Files (x86)\NSIS\makensis.exe" installer\PDF-Equilibrist.nsi

# → installer\Output\PDF-Equilibrist-Setup.exe
```

### Ce que l'installeur fait

- Installation **sans droits administrateur** (HKCU, `%LocalAppData%`)
- Raccourci Menu Démarrer
- Association `.pdf` → "Ouvrir avec PDF Equilibrist"
- Entrée dans "Programmes et fonctionnalités" avec désinstalleur propre
- Option raccourci Bureau (case à cocher)

### Injection de la version depuis le tag git

Le script NSIS supporte un paramètre de version pour CI/CD :

```powershell
makensis /DAPP_VERSION=1.2.3 installer\PDF-Equilibrist.nsi
```

## CI/CD — Build automatique sur tag GitHub

`.github/workflows/release.yml` — déclenché par un tag `v*` ou manuellement
(`workflow_dispatch`) :

```
tag v0.1.4
    └── release.yml
         ├── Resolve version         → extrait "0.1.4" du tag ou de l'input
         ├── setup-python 3.12
         ├── pip install -r requirements.txt + pyinstaller
         ├── python tools/prepare_build.py
         ├── pyinstaller PDF-Equilibrist.spec
         ├── choco install nsis
         ├── makensis /DAPP_VERSION=0.1.4  → installer\Output\PDF-Equilibrist-Setup.exe
         ├── Sign installer (si SIGNING_CERT_PFX_B64 configuré)
         └── softprops/action-gh-release@v2
              ├── generate_release_notes: true   ← changelog auto depuis commits
              └── files: PDF-Equilibrist-Setup.exe
```

Déclenché par : `git tag v1.2.3 && git push --tags`

**Notes de release automatiques** : `generate_release_notes: true` génère
le changelog à partir des commits et pull requests depuis le tag précédent.

## Signature de l'installeur (optionnelle)

La signature de code élimine l'avertissement SmartScreen Windows et prouve
l'origine de l'exécutable. Elle est configurée via deux secrets GitHub :

| Secret GitHub | Contenu |
|---|---|
| `SIGNING_CERT_PFX_B64` | Certificat PFX encodé en Base64 |
| `SIGNING_CERT_PASSWORD` | Mot de passe du PFX |

### Encoder le certificat PFX

```powershell
$bytes = [IO.File]::ReadAllBytes("mon-certificat.pfx")
[Convert]::ToBase64String($bytes) | Set-Clipboard
# Coller dans GitHub → Settings → Secrets → SIGNING_CERT_PFX_B64
```

### Comportement du workflow

- Si `SIGNING_CERT_PFX_B64` est absent ou vide → l'étape de signature est
  ignorée silencieusement (build continue sans erreur).
- Si `signtool.exe` est introuvable dans Windows Kits → même comportement.
- L'installeur signé remplace l'unsigned avant upload sur GitHub Releases.

### Signature locale (hors CI)

```powershell
signtool sign /f mon-certificat.pfx /p motdepasse /fd SHA256 `
    /tr http://timestamp.digicert.com /td SHA256 `
    installer\Output\PDF-Equilibrist-Setup.exe
```

## Enregistrement Windows "Ouvrir avec..."

Après la première installation :

```powershell
# Enregistrement automatique via Python (HKCU — pas de droits admin)
python tools/register_filetype.py --exe "D:\...\dist\PDF-Equilibrist.exe"

# Désinstallation
python tools/register_filetype.py --exe "D:\...\dist\PDF-Equilibrist.exe" --unregister
```

L'enregistrement est aussi effectué **automatiquement** au premier lancement
de l'exe compilé (via `registration.auto_register()` dans `main.py`).

## Double-clic et "Ouvrir avec..."

Une fois enregistré, l'exe peut être lancé avec un chemin PDF en argument :

```cmd
PDF-Equilibrist.exe "C:\Documents\rapport.pdf"
```

Windows passe automatiquement le chemin via `sys.argv[1]` lors d'un double-clic
ou d'un "Ouvrir avec...". `main.py` ouvre le fichier dans un onglet après
l'initialisation de la fenêtre.

Pour définir PDF Equilibrist comme **application par défaut** pour les PDF :
`Paramètres Windows → Applications → Applications par défaut → .pdf`

## Distribution Linux et OCR

Canaux actifs : **Windows** (installeur NSIS), **Ubuntu** (PPA, noble + resolute), **Fedora** (COPR)
et **Arch Linux** (AUR), plus un fichier **AppImage** pour toutes les autres distributions. L'OCR
(RapidOCR + ONNX Runtime) est présent sur les cinq : les modèles
`.onnx` (~30 Mo) sont livrés *dans* la wheel `rapidocr`, jamais téléchargés.

| Canal | Où vivent les dépendances OCR | Vérification avant publication |
|---|---|---|
| Windows | PyInstaller embarque `rapidocr` + modèles (`collect_data_files`) | `ci.yml` / `release.yml` : `PDF-Equilibrist.exe --ocr-selftest` sur l'exe figé |
| PPA | Wheelhouse vendorisé (`packaging/ppa/fetch_wheelhouse.sh`, source unique de la liste), venv privé `/usr/lib/pdf-equilibrist/venv` | `debian/rules` lance l'auto-test à la fin du build ; `linux-packages-check.yml` construit et teste noble et resolute |
| COPR | Wheels `rapidocr` + `omegaconf` vendorisées ; onnxruntime, shapely, pyclipper… via les paquets Fedora | `%check` du `.spec` ; `linux-packages-check.yml` (Fedora 44) |
| AppImage | PyInstaller (`packaging/appimage/PDF-Equilibrist-linux.spec`) embarque tout, `rapidocr` et modèles compris ; construite sur Ubuntu 22.04 (glibc 2.35) | `linux-appimage.yml` : auto-test OCR réseau interdit, puis lancement sur Debian 12, Ubuntu 24.04, Fedora 44, Arch et openSUSE avant publication |
| AUR | Wheel `rapidocr` en source du `PKGBUILD` (somme de contrôle) ; le reste via les paquets officiels (`python-onnxruntime`, `python-shapely`…) | `linux-aur.yml` / `linux-aur-publish.yml` : auto-test sur le paquet construit |

L'auto-test (`--ocr-selftest`) génère une page « scannée », lance l'OCR avec **toute connexion réseau
interdite** et vérifie que le texte français (accents compris) est reconnu. Les workflows de
publication PPA et COPR dépendent de ces vérifications : aucune release Linux n'est publiée avec un
OCR annoncé mais non fonctionnel.

**AppImage.** Un tag `v*` déclenche `linux-appimage.yml`, qui construit l'AppImage, la teste sur les
cinq distributions, puis la joint à la release GitHub avec son `.sha256` et `install.sh`
(`packaging/appimage/install.sh` : installation sans root dans `~/.local` ou `--system` dans `/usr/local`,
désinstallation avec `--uninstall`). Pour joindre l'AppImage à une release existante : lancer le workflow à la
main avec le champ `tag`. Dans l'application, *Aide › À propos* détecte l'AppImage (variable `APPIMAGE`),
télécharge la nouvelle version (SHA-256 vérifié) puis propose de l'installer avec le `install.sh` embarqué dans
l'AppImage : pour l'utilisateur seul (sans mot de passe) ou pour tous les utilisateurs (autorisation demandée par
le système via `pkexec` ; l'application ne voit jamais le mot de passe, et la somme SHA-256 est revérifiée en root
sur une copie avant l'installation). Elle propose ensuite de relancer la nouvelle version.

> **Flatpak : temporairement suspendu.** Aucun développement, packaging ni test Flatpak n'est prévu
> pour l'instant, et l'OCR n'y est pas inclus. Les fichiers existants (`packaging/flatpak/`) sont
> conservés pour une reprise ultérieure ; il suffira alors d'ajouter `rapidocr` et `onnxruntime` au
> manifeste.

## Dépannage build

### L'exe crashe au démarrage (zlib / vcruntime)

Vérifier que `upx_exclude` dans le spec contient bien :
```
"zlib1.dll", "vcruntime140.dll", "msvcp140.dll",
"Qt6Core.dll", "Qt6Gui.dll", "Qt6Widgets.dll"
```

### Module manquant à l'exécution (ImportError)

Ajouter le module dans `hiddenimports` du spec et recompiler.

### Assets non trouvés (FileNotFoundError)

Vérifier que le dossier est bien dans `datas` du spec.
Vérifier l'utilisation de `resource_path()` dans le code (pas de chemins relatifs durs).

### Antivirus bloque l'exe

Les exes PyInstaller onefile sont parfois signalés (faux positif).
Solutions : signer l'exe (certificat EV), soumettre à la whitelist de l'antivirus,
ou utiliser le mode `onedir` (dossier + exe) moins sujet aux faux positifs.
